# gridsearch

Homemade package for solving tricky numerical problems (e.g. politico-economic equilibria without closed-form solutions) via gridsearch/root-finding methods, shared across the model variants.

## Files
- `__init__.py` — imports `robustRoot`, `roots1d`, `cartesian`, `interp`; re-exports `CartesianGrid`, `griddedInterp1D`.
- `robustRoot.py` — the bounded-root reparameterization from `writing/informalAnalytical_docs.tex`'s "Robust root finding with bounds" (`eq:root`): wraps a first-order-condition function `f` (only meaningful on `[l,u]`, e.g. a tax rate on `[0,1]`) into an unconstrained residual `h(z,τ)` that a gradient-based root-finder can search over all of `ℝ` without ever calling `f` outside its safe domain. Model-agnostic (takes `f` as a plain callable, no dependency on any specific model's `db`/`base.py`), so it's meant to be reused across `informalAnalytical`/`InformalSavings`/`US`'s policy solves, not just the one that motivated it.
  - `clip(τ, l=0, u=1)` — `[τ]_{[l,u]}`.
  - `penalty(τ, l, u, a0, a1)` — `g(τ)`, the out-of-bounds linear-penalty driver (0 inside `[l,u]`).
  - `boundedResidual(f, l, u, a0, a1)` — returns the callable `h(τ)`; `f` is only ever evaluated at `clip(τ,l,u)`. Recover the actual bounded policy from a solved `τ̃` via `clip(τ̃, l, u)`.
  - Verified against the doc's own worked examples (well-behaved interior root; both one-sided "always positive/negative on `[0,1]`" boundary cases) — reproduces the exact analytical roots (`τ̃=1+1/a1`, `τ̃=-1/a0`) the doc derives by hand.

- `roots1d.py` — one-dimensional root and extremum detection on a grid (`writing/informalAnalytical_docs.tex`'s `alg:gridsearch`). Takes a sorted grid `x` (M,) and values `f` (M,) or (M,N) — N independent functions sampled on the *same* grid — and locates where the piecewise-linear interpolant of `f` crosses zero. Model-agnostic like `robustRoot`.
  - **Two families**, differing only in which crossings count. `allRoots`/`firstRoot` (`kind='any'`) for genuine root problems, where any crossing solves. `allMax`/`firstMax` (downward crossings) when `f` is the derivative of an objective and only maxima are admissible — e.g. the political FOC `z_t`, where an upward crossing is a local *minimum* of the political objective. `allMin`/`firstMin` for the mirror case. `allRoots` returns `(Kmax, N)` NaN-padded so the genuinely ragged result stays usable in vectorized downstream code.
  - **Exact zeros are always handled**, at any `tol`, via a sign-run rule (nodes with `|f| <= tol` are skipped when pairing signs). This is not an edge case: under `robustRoot` a corner solution is encoded as an *identically* zero value at an outer node (`h = z + |z| = 0` when `z < 0`), which `f[i]*f[i+1] < 0` cannot see. Zeros at the grid's own first/last node — precisely where corners land — get one-sided direction classification.
  - `tol` defaults to `0`: a nonzero default would report spurious roots wherever `f` merely grazes zero without crossing, which for maximum-detection is a real error rather than a rounding detail.
  - **Multiplicity**: `objectiveProfile(x, f)` is the cumulative trapezoid, which is the integral of the *same* piecewise-linear interpolant used to locate crossings — exactly, not approximately. `selectMax(x, f)` then returns the global maximiser over the candidate set `{x[0], x[-1]} ∪ {downward crossings}`, plus `nMax` (multiplicity flag) and `atBound`. This subsumes the boundary check rather than supplementing it: the endpoints compete with interior maxima on the same footing. Pass the *interior* grid only — outside `[l,u]` the penalised residual `h` is an artificial construction, not `dV/dτ`, so integrating it would be meaningless.

  - **Vectorized across columns.** `_matrixCrossings` detects crossings in every column at once, with no Python loop over columns. The one apparently-sequential part of the rule — "pair each node with the last *nonzero* node before it", whose reach varies by column and position — vectorizes via `np.maximum.accumulate` on the row indices, carrying forward the most recent nonzero node. Crossings are sparse, so the gathers and interpolation run only at the indices where one actually occurs (`np.nonzero`), which is what keeps the `(M,N)` temporaries down; compaction into the padded layout is a `lexsort` over the crossings alone, never over the full grid height. **4–8x** faster than looping in the intended range (`M ~ 10²` nodes, `N ~ 10²` states); the loop wins again past ~5·10⁶ elements, where cache locality beats fewer Python calls. `_columnCrossings` is retained as the readable statement of the rule and as the **test oracle** — the two are checked for exact agreement on 1200 randomized cases (400 inputs × 3 kinds), deliberately including zero runs, boundary zeros and all-zero columns.
  - `selectMaxND(grid, f, name)` — `selectMax` over a `CartesianGrid`: searches along axis `name`, returns one solution per state combination reshaped to `grid.stateShape(name)`. Duck-typed (needs only `.values`/`.asColumns`/`.stateShape`), so `roots1d` stays a self-contained module about crossings on a grid with no dependency on how the grid was built.

- `cartesian.py` — `CartesianGrid`, the Cartesian product of named 1d grids and the flat↔ND mapping. Lets a grid search evaluate the model's equations **once**, on flat vectors covering every (choice, state) combination, then look along the choice axis alone. Numpy only.
  - **Why not a pandas MultiIndex** (as `inspiration/gridsearch` used, recovering the matrix via `unstack`): when the product is built here in C-order, the flat layout is fixed by construction, so `reshape` inverts it *exactly* and cheaply — no sorting, no label lookups, no dependence on `unstack`'s level ordering. Labels can still be attached for reporting; the solve path stays plain ndarrays.
  - `.flat` → `{name: (size,) vector}`, cached — feed straight in as `f(**g.flat)`. `.reshape(y)` → `shape + trailing`, so per-type `(points, ni)` arrays survive. `.asColumns(y, name)` → `(M, N)` for `roots1d`. `.stateShape(name)` → the shape a per-state result reshapes back to.
  - Nothing requires the choice axis to be first; `asColumns` moves whichever axis is named to the front.

- `interp.py` — three jobs on gridded `(x, y)` data. `griddedInterp1D(x, y, kind='linear')`: a callable interpolant (e.g. a solved policy `τ(s)`/`h(s)`), evaluable at an arbitrary candidate state — thin wrapper around `scipy.interpolate.interp1d(..., fill_value='extrapolate')`, chosen over porting the inspiration's hand-rolled `CustomLinInterp`. **Extrapolates, does not clamp** — a candidate state from an outer root-solve need not land inside the grid. `griddedSmooth1D`/`griddedGradient1D(x, y, s, k)`: a smoothing-spline denoise pass / derivative along a grid axis, sharing one `UnivariateSpline` fit (`_splineAlongAxis0`); NaN passes through per-column rather than poisoning the fit (real infeasible cells, not defensive padding).

- `test_roots1d.py` — standalone regression tests for `roots1d`, `cartesian`, and `interp` (assertions: interpolation accuracy, direction filtering, exact zeros on interior and boundary nodes, zero runs, `tol` behaviour, N-column vectorization, exactness of `objectiveProfile`, `selectMax` on multi-peaked objectives and corners, end-to-end integration with `robustRoot`'s corner encoding, the vectorized-vs-oracle equivalence sweep, `CartesianGrid` round-trips/column ordering/`selectMaxND`, and `griddedInterp1D`'s node-exactness/linearity/sorting/extrapolation/trailing-axis behaviour). Run it directly: `.venv\Scripts\python.exe python\gridsearch\test_roots1d.py`. No test framework — it prints PASS/FAIL per assertion and a final verdict, matching the repo's script-style `test.py` convention. `informalAnalytical/test_crraTerminal.py` covers the *integration* — `griddedInterp1D` actually feeding `CRRA.report_T`'s `τPolicy`/`hPolicy`.

## Implementation status
`robustRoot`, `roots1d` (incl. NaN/infeasibility handling in `selectMax`), `cartesian`, and `interp` (all three functions) are implemented and tested — all four consumed by `informalAnalytical.policy`'s `LOG` and `CRRA` classes end to end (terminal period and the `t<T` backward recursion). Nothing else in this package has been started — the `InformalSavings`/`US` variants will likely need all four once their policy solves require numerical root finding.

## Not ported from `inspiration/gridsearch` (deliberately)
The inspiration's `SolveGrid` class does a lot of work to precompute index maps and to avoid evaluating the full grid. Most of it addresses a cost this design removes, so it is being left out until something actually needs it:
- **Traversal order + per-state warm starts** (`_createTraversalOrder`, `GSLoop_i`) — exists because the inspiration solved state-by-state in a Python loop. Evaluating the whole Cartesian grid in one vectorized pass removes the loop, so there is nothing to warm-start.
- **`ΔL`/`ΔU` refinement + `estimate_refinement_from_full_solution`** — refinement exists to avoid evaluating the full grid, but a FOC evaluation's cost is dominated by per-call db overhead and is **flat in grid size** (`M=101` and `M=501` both ~1.8ms; see `informalAnalytical/README.md`'s "Base conventions"). Refining currently optimizes a non-problem. Revisit at `t<T`.
- **`fallback_to_nn`, `_fillNaN2D`, `_smooth2D_robust`** — handle infeasible state/choice combinations, which only arise at `t<T` once an *approximated* state can fall off-grid. Not reachable at the terminal period.
- **Index maps for `np.ix_` subsetting** — numpy `reshape` on a self-built C-order product is free, so these have no counterpart to earn.

What the precompute-once principle *did* justify is a cache of per-**year** db parameters — see `base.py`'s `cacheParams()`. That is the repeated cost here, and it is a model concern rather than a grid one.
